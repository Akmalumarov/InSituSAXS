# AGENTS.md — InSituSAXS: анализ in situ SAXS/WAXS полимеров

## 0. Цель и образ результата

Разработать воспроизводимый пайплайн обработки и анализа синхротронных данных
(in situ) SAXS/WAXS для полимерных материалов: от сырых кадров до кривых I(q) и
их эволюции во времени. Работа ведётся с данными станций ESRF
BM26, ID02, ID13 и других синхротронов.

В конце работы в проекте существуют:
- `src/` — воспроизводимый Python-код выполненного анализа;
- `results/` — результаты анализа в требуемых форматах (таблицы, графики, текст, кривые);
- `diary.md` — запись о выполненной работе и способе проверки. Указывать названия скриптов, использованных для анализа.

Не создавать файлы и директории, не относящиеся к текущей задаче.


## 1. Критерий готовности

Работа считается выполненной, когда проходит **сверка**:
1. Поиск пиков и анализ структурного фактора:
  проверка на синтетических данных из `data/synthetic/` с известными положениями и параметрами пиков. Относительная погрешность положения по q: 5% (сверка с `checks/`)

1. Фитирование I(q) = P(q)S(q) или I(q) = P(q):
  проверка на синтетических данных из `data/synthetic/` с известными параметрами модели. Относительная погрешность основных структурных параметров (радиусы, длины) не более 10% относительно эталонных значений.

1. Определение кристаллических фаз (WAXS):
  сверка положения пиков с литературой `references/`. Запросить разрешение на чтение pdf, если нет готового *.md с положениями пиков или кратким содержанием статей. Относительная погрешность положения по q: 3%. 

Для задач с подготовленной независимой проверкой агент запускает:

python3 checks/check.py

Агент не должен читать или изменять содержимое checks/.
Если независимая проверка невозможна, агент сообщает об этом и не объявляет научный результат подтверждённым.
Результат проверки записывается в diary.md.

## 2. Карта проекта и источники

- `data/` — Экспериментальные и синтетические данные
- `src/` - Python-скрипты и модули для анализа данных. Методом будем называть группу скриптов для общей задачи.
- `notebooks/` - Jupyter-ноутбуки исследователя. Агент может читать их, но не изменять без явного запроса.
- `results/` - Результаты обработки (тексты, графики, таблицы, новые кривые)
- `references/` - Статьи / методички / руководства. Читать только в случае явного запроса.
- `memory/` - Заметки по методам обработки / видам станций и образцов. Заполнять очень краткой и потенциально полезной информацией для будущих обработок схожих систем.
- `diary.md` - Журнал работы агента. Заполняется после каждой завершенной задачи.
- `tasks/` - папка с задачами для ИИ-агента. Исследователь ставит задачу либо через терминал либо просит посмотреть конкретный файл в tasks. 

## 3. Инструменты и границы

1. Все скрипты для анализа пишутся на Python. Используются специализированные библиотеки (numpy, scipy, pyFAI, matplotlib).
2. Скрипты пишутся универсально (при возможности без привязки к исследуемой системе).
3. Скрипты должны легко импортироваться и использоваться в Jupyter-ноутбуках исследователя. При организации модулей в Python-пакеты использовать __init__.py.

## 5. Протокол работы

Режим работы: **план и исполнение**.

1. **Анализ задачи** Перед началом работы агент прочитывает `diary.md`, скрипты в `src/` по необходимому методу. Если задача ставилась раньше, агент ищет в `memory/` записки по конкретному методу. Составляется краткий план работы на 3-6 шагов.
2. **Исполнение** Агент самостоятельно выполняет план работы. Приоритет - использование существующих скриптов.
3. **Выполнение и проверка** Агент запускает свой код и проверяет ход исполнения и отсутствие ошибок. Если существует независимая проверка, она запускается через `python3 checks/check.py`.
4. **Анализ ошибок** При провале агент анализирует причины, исправляет код и запускает снова. Разрешено три цикла исправлений. Исправления научных алгоритмов должны иметь математическое или физическое обоснование. Если обоснование отсутствует, агент обращается к исследователю.
5. **Заполнение дневника** После завершения агент дополняет `diary.md`: выполненные задачи, нерешенные проблемы, полученные результаты (кратко). Полезные новые знания о методе заполняются в `memory/`.
6. **Сохранения** Успех — код выполняется без ошибок, предусмотренные независимые проверки пройдены, результаты сохранены. После успешного завершения задачи агент может создать локальный git-коммит только с относящимися к задаче файлами. Если независимая проверка отсутствует, агент сообщает об этом и не создаёт коммит без разрешения исследователя.

## 6. Память

1. `diary.md` только дополняется, прошлые записи не удаляются. время выполнения задачи, расход токенов и количество запусков скриптов, если эти данные доступны. Не оценивать расход токенов на глаз.

3. формат локального git-коммита: `исследуемая система: краткая задача`
