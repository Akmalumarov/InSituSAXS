# AGENT.md — InSituSAXS: анализ in situ SAXS/WAXS полимеров

## Цель проекта
Разработать воспроизводимый пайплайн обработки и анализа синхротронных данных
(in situ) SAXS/WAXS для полимерных материалов: от сырых кадров до кривых I(q) и
их эволюции во времени. Результат — набор скриптов в `src/`, графики и таблицы,
пригодные для отчёта и статьи. Работа ведётся с данными станций ESRF
BM26, ID02, ID13 и других синхротронов.

Агент должен помогать:
- читать и проверять экспериментальные данные;
- разрабатывать и запускать код обработки;
- извлекать структурные параметры;
- анализировать их эволюцию во времени/температуре;
- документировать вычисления и способы их проверки.

Результаты проекта должны быть воспроизводимы из исходных данных
с помощью кода из `src/`.


## Данные и материалы
- `data/` — исходные кадры и сопутствующие файлы:
  - **BM26** — 2D-кадры в формате *.edf (SAXS/WAXS) + проинтегрированные данные в формате *.dat
  - **ID02** — 2D-данные в формате HDF5 (SAXS высокого разрешения, Fast Scanning Calorimetry):
    - `RAW_DATA/` — исходные h5;
    - `PROCESSED_DATA/` — предобработанные данные (ave, azim, norm);
  - **ID13** — 2D-данные в формате HDF5 (WAXS высокого разрешения и нанокалориметрия).
  - `RAW_DATA/` — исходные h5;
  - `PROCESSED_DATA/` — предобработанные данные (ave, azim, norm);

- `results/` — статьи, черновики, иллюстрации.
- `notebooks/` — интерактивные ноутбуки (фитирование, разведка). Всё, что можно
  вынести в `src/` (модули, функции, константы), живёт вне ноутбуков.
- Исходные данные не изменять; производные файлы — в `memory/` или отдельных
  подпапках, но не в `data/`.

## Структура
```
InSituSAXS/
├── AGENT.md       договор с ИИ-агентом
├── diary.md       журнал задач и проверок
├── data/          исходные данные (только чтение)
├── src/           модули и скрипты (весь код вне ноутбуков)
├── notebooks/     интерактивные ноутбуки (тонкие, импортируют из src/)
├── memory/        заметки, сводки, промежуточные артефакты
├── results/       графики, таблицы, черновики
└── references/    PDF-статьи и руководства
```
Тесты не используются: корректность проверяется запуском кода и сверкой
с источником/данными.

## Работа
- Читать существуюшие скрипты и создавать новые.
- Код — в `src/`, запускать перед тем, как сообщать результат.
- Каждый вывод сопровождается способом его проверки: скрипт, ручной пересчёт,
  сверка с источником, визуальный контроль графика.
- Сводки и заметки для следующих сессий — в `memory/`. Там же теория для обработки по разным методам.

## Журнал
- После каждой задачи — запись в `diary.md`: дата, запрос, что сделано,
  результат, точка проверки, итог проверки. Старые записи не менять.
